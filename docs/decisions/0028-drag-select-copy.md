# 0028. 대화 본문 드래그 선택과 복사

상태: 채택 (2026-11-27)

## 배경

마우스를 잡으면(0024) 터미널의 드래그 선택은 shift(iTerm2 는 option)를 눌러야 한다. 눌러서 고르더라도
왼쪽 여백과 오른쪽 스크롤바(`│┃◆`)가 같이 복사되고, 화면 밖으로 넘어간 부분은 고를 수 없다.
`--no-mouse` 는 휠 스크롤까지 잃는다.

## 결정

- 대화 본문에서 왼쪽 버튼을 누른 채 끌면 앱이 직접 선택한다(`src/tui/select.lis`). `MouseModeCellMotion` 이
  이미 누름, 끌기, 놓기를 보내므로 마우스 모드는 그대로다.
- 위치는 화면 좌표가 아니라 viewport 내용의 `TextPos { line, col }`(표시 열, 한글 2열)로 `ConvView.sel` 에 둔다.
  그래서 휠이나 키로 스크롤해도 선택이 글자를 따라간다. 두 끝을 모두 포함하고, 끄는 방향은 상관없다.
- 누르기만 하고 놓으면(움직임 없음) 선택이 아니다. 헤더나 하단 줄에서 누르면 시작하지 않는다.
  끄는 중 본문 위나 아래로 벗어나면 그쪽으로 한 줄 스크롤한다. CellMotion 은 움직일 때만 이벤트가 오므로
  가만히 있으면 멈춘다(타이머로 계속 스크롤하지 않는다).
- 표시: `body_view` 가 보이는 줄마다 `highlight_row` 로 선택 열을 반전(`st_select`)한다. 앞뒤 조각은 `ansi.Cut` 이
  escape 를 보존하므로 색이 그대로고, 가운데는 글자만 남겨 반전한다. 줄 끝 공백(glamour 의 채움)은 칠하지 않는다.
- 키(대화 화면)
  - `y`: 선택을 클립보드에 담고 선택을 지운다. 선택이 없으면 안내만 한다.
  - `Y`: `claude --resume <id>` 복사(전에는 `y`). 목록 화면의 `y` 는 그대로 resume 복사다.
  - `esc`: 선택이 있으면 먼저 선택만 지운다. 다음 `esc` 부터 전과 같다.
  - 선택이 있으면 하단 줄 힌트가 `Copy y | Clear esc` 로 바뀐다.
- 복사 글: 내용 줄에서 ANSI 를 벗기고 선택 열을 잘라 줄 끝 공백을 지운다(`selected_text`). 공백뿐이면 복사하지 않는다.
  화면에 그려진 글이므로 마크다운 원문이 아니다. 클립보드는 `atotto/clipboard`, 실패하면(SSH 등)
  `tea.SetClipboard`(OSC 52)로 보낸다.
- 다시 배치(relayout)되면 선택의 두 끝을 메시지 기준으로 옮긴다(`remap_selection`): 그 끝이 속한 span 의 메시지를
  새 spans 에서 찾아 같은 오프셋에 둔다. 메시지가 사라졌거나 줄 수가 바뀌었으면 선택을 지운다. 지연 렌더(0006)와
  모니터링의 새 메시지 추가는 대부분 선택 밖이라 선택이 남는다. 보기 토글, 역할 순환, 창 크기 변경은 줄 구성이 통째로
  바뀌므로 옮기지 않고 지운다.
- 선택은 `Mode.Normal` 에서만 시작하고 끈다. 모달, 검색 입력 중, 창이 너무 작을 때는 무시한다(0024 와 같은 이유).

## 검토한 대안

- 메시지 단위 원문(마크다운) 복사: 원문이 필요할 때 더 쓸모 있지만 이번 범위에서 뺐다. `span_at` 으로 쉽게 붙일 수 있다.
- 놓을 때 바로 복사: 키 없이 편하지만 클립보드를 의도치 않게 덮어쓴다. vim 처럼 고른 뒤 `y` 로 담는다.

## 테스트

`src/tui/select.test.lis`. 끌기, 놓기 메시지는 `shim.Drag`, `shim.Release` 로 만든다. 클립보드를 건드리지 않도록
테스트는 `selection_text` 를 보고 `y` 는 선택이 없을 때만 누른다. 실제 터미널은 tmux 에 SGR 시퀀스
(`ESC [<0;x;yM` 누름, `ESC [<32;x;yM` 끌기, `ESC [<0;x;ym` 놓기)를 넣어 반전 표시, 힌트, `y` 복사를 봤다.
