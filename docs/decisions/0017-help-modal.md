# 0017. 도움말 모달과 모달 공통 표시 방식

상태: 채택 (2026-10-25)

## 배경

도움말(`?`)은 화면 전체를 바꾸는 왼쪽 위 상자였고, 키와 설명이 한 줄에 이어져 정렬되지 않았다.
삭제 확인 창과 제목 변경 창도 `lipgloss.Place` 로 빈 화면 가운데에 그려져 지금 보던 화면이 사라졌다.

## 결정

- 도움말 내용(`help.lis`): 묶음(공통, 이동, 목록, 입력, 대화, 표식)마다 키와 설명 목록. 설명은 짧게(열 폭을 줄이려고).
  묶음 순서는 열로 나눌 때 높이가 고르도록 정했다(입력은 목록 필터 뒤).
- 열 배치: 본문 폭(`화면 폭 - 6`, 최대 120) 안에 들어가는 가장 많은 열 수(최대 3)를 고르고, 묶음 순서를 지키는
  나누기 중 가장 높은 열이 가장 낮은 것, 같으면 열 높이가 고른 것. 한 열도 넘치면 한 열로 두고 설명을 `…` 로 줄인다.
  열마다 키 칸 폭을 맞춰 설명을 세로로 정렬한다. 열 사이 4칸, 키와 설명 사이 2칸.
  130칸은 3열(높이 26), 80~100칸은 2열(31), 그보다 좁으면 1열(58).
- 상자(`framed_box`): 둥근 테두리, 위 테두리에 제목 `키 바인딩`, 아래 테두리에 키 안내(`scroll j k | close esc`)와
  스크롤 위치(`1-20/31`). 테두리 색은 기존 상자와 같은 `st_border`.
- 스크롤: 상자 안에 보이는 줄은 `화면 높이 - 4` 까지. `j k ↓ ↑` 한 줄, `d u ^d ^u ^f ^b PgDn PgUp space` 한 화면,
  `g G Home End` 처음/끝. 그 밖의 키는 닫기만 한다(`q` 도 종료가 아니라 닫기). 내용이 다 들어가면 스크롤 안내와 위치를 숨긴다.
- 모달 표시(`overlay`): 지금 화면을 그린 뒤 색을 벗겨 흐리게 깔고, 그 위 가운데에 상자를 얹는다.
  도움말, 삭제 확인 창, 제목 변경 창이 모두 이 방식이다(각 view 는 상자만 돌려준다).
  - 넓은 글자가 상자 왼쪽/오른쪽 경계에 걸리면 그 글자를 빼고 빈칸으로 채운다.
    `ansi.TruncateLeft` 는 경계에 걸린 넓은 글자를 남겨 줄이 화면보다 넓어지므로 남는 폭을 넘으면 앞 글자를 뺀다.
  - 화면보다 넓은 상자는 잘라 낸다. 삭제 확인 창은 경로를 화면 폭에 맞춰 줄인다(기존에는 90칸 고정이라 100칸 화면에서 넘쳤다).
- 도움말 내용은 0016 범위대로 한글. 상자 테두리의 키 안내만 영문.

## 검증

- `src/tui/help.test.lis`: 폭별 열 수와 줄 폭, 1열에서 설명 시작 칸 정렬, 테두리 상자의 제목/키 안내/위치와 줄 폭,
  overlay 의 가운데 배치와 크기 유지, 넓은 상자 자르기, 넓은 글자 경계, 도움말 모달의 배경 유지와 j/k/G/g 스크롤,
  `q` 로 닫힐 뿐 종료되지 않음.
- tmux: 130x34(목록, 대화 위 3열), 100x26(2열, 스크롤 위치), 80x24(G 로 끝), 50x16(1열), 삭제/제목 변경 창 overlay,
  `--no-color` 색 코드 0개.
