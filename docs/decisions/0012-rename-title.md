# 0012. 세션 제목 변경 (R)

상태: 채택 (2026-10-24)

## 결정

- 키: 목록과 대화 화면 모두 `R`(shift+r). `D` 삭제와 짝을 맞춘다. 목록의 새로고침은 `ctrl+r` 만 남긴다
  (기존 `R` / `ctrl+r` 에서 `R` 을 제목 변경으로 옮김). 대화 화면의 `r` 역할 순환은 그대로.
- 저장 방식: Claude Code 의 `/rename` 과 같이 세션 jsonl 끝에
  `{"type":"custom-title","customTitle":"<제목>","sessionId":"<id>"}` 한 줄을 덧붙인다.
  파서는 마지막 custom-title 을 쓰므로(0002) 기존 줄은 고치지 않고, `claude --resume` 목록에도 같은 제목이 보인다.
  파일이 개행으로 끝나지 않으면 줄이 섞이지 않게 개행을 먼저 넣는다. `O_APPEND` 한 번의 쓰기로 붙인다.
- 경로 검증: 삭제(0005)의 화이트리스트를 `session.check_session_path` 로 떼어 내 함께 쓴다
  (절대 경로, `..` 없음, uuid 이름, projects 바로 아래 프로젝트, 심볼릭 링크 아님, 실경로 일치).
  실행 중인 세션도 막지 않는다. Claude Code 도 같은 방식으로 덧붙이므로 덧붙이기끼리 충돌하지 않는다.
- 제목 정리(`clean_title`): 줄바꿈/탭은 공백, 앞뒤 공백 제거, 200룬까지. 비었거나 그대로면 쓰지 않는다.
- 입력창: 기존 표시 제목을 채워서 연다. `enter` 저장, `esc` 취소, `backspace`, `ctrl+u` 모두 지우기.
  입력 중에는 단축키가 동작하지 않는다(0010). 긴 입력은 커서 쪽 끝부분을 보여준다.
- 저장 후에는 모니터링 이벤트와 같은 경로(`on_files`)로 목록 메타와 열린 대화를 파일에서 다시 읽는다.
- 목록의 묶음과 표시 시각은 정렬 기준인 파일 수정 시각(mtime)을 쓴다. 제목 변경처럼 메시지 없이 파일만 바뀌면
  마지막 메시지 시각과 mtime 이 어긋나 묶음 제목이 정렬과 반대로 보였기 때문이다. 바뀐 세션은 맨 위(오늘)로 올라간다.

## 검증

- `src/session/rename.test.lis`: 제목 정리, 덧붙이기(개행 없는 파일, 기존 줄 보존, 두 번 바꾸면 마지막 제목),
  빈 제목/projects 밖/세션 파일 아님/상대 경로 거부.
- `src/tui/app.test.lis`: 목록과 대화 화면에서 `R`, `esc` 취소 시 파일 그대로, 입력 중 `q` 무시, `ctrl+r` 새로고침.
- tmux 90x16: 입력창 표시, 한글 입력, 저장 후 목록 제목/순서/커서 유지, jsonl 마지막 줄 확인.
