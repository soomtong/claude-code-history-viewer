# 0024. 마우스: 휠 스크롤과 목록 클릭

상태: 채택 (2026-11-10)

## 배경

`View` 가 `MouseMode` 를 정하지 않아 터미널이 마우스 이벤트를 보내지 않았다. 대체 화면(alt screen)에서는
휠이 터미널 스크롤백으로 가지도 않아 휠을 굴려도 아무 일이 없었다. bubbles viewport 의 휠 처리
(`MouseWheelEnabled`)는 켜져 있었지만 이벤트가 오지 않으니 쓰이지 않았다.

## 결정

- `View` 에서 `opts.mouse` 면 `tea.MouseModeCellMotion` 을 켠다. 클릭, 놓기, 휠, 누른 채 끌기만 받고
  움직임만으로는 이벤트가 오지 않는다(`AllMotion` 은 쓸 일이 없어 이벤트만 늘린다).
- 처리(`src/tui/mouse.lis`)는 휠(`on_wheel`)과 왼쪽 클릭(`on_click`)만. 나머지 마우스 메시지는 버린다.
  입력창이 열려 있어도 마우스 메시지는 textinput 으로 넘기지 않는다.
  - 대화: 휠 한 칸에 본문 `WHEEL_LINES`(3, viewport 기본값과 같음) 줄. 키 스크롤과 같이 보이는 범위를
    렌더하고 끝에 닿으면 새 메시지 수를 지운다(`after_scroll`). 화면 어디서 굴려도 본문이 움직인다
    (헤더와 하단 줄은 스크롤할 것이 없다). 가로 휠은 무시. viewport.Update 에 맡기지 않고 직접 처리해
    shift+휠이 가로 스크롤로 바뀌는 동작을 피한다.
  - 목록: 휠 한 칸에 선택 한 항목. 목록은 커서가 보이는 범위를 정하므로(clamp_list) 커서를 움직이는 것이
    키 동작과 일관된다.
  - 도움말: 상자 안을 `WHEEL_LINES` 줄씩.
  - 클릭은 목록에서만. 항목(제목, 메타 줄)을 누르면 선택, 이미 선택된 항목을 다시 누르면 연다.
    더블클릭 판정(시간 창)을 두지 않아 상태가 단순하다. 필터 입력 중에는 선택만 한다.
    y 좌표는 `list_row_at` 이 헤더 1줄 + 필터 1줄을 뺀 뒤 `list_layout` 에서 찾는다.
  - 삭제 확인, 제목 변경 모달, 창이 너무 작을 때는 무시한다(키와 같은 이유: 안 보이는 동작 방지).
- 끄기: `--no-mouse`, 설정 `mouse = false`(기본 true). 마우스를 잡으면 터미널의 드래그 선택은 보통
  shift(iTerm2 는 option)를 눌러야 하므로, 평소 선택 복사를 자주 하는 사용자를 위한 탈출구다.
  꺼져 있으면 혹시 들어온 마우스 메시지도 버린다.

## 테스트

`src/tui/mouse.test.lis`. 테스트 메시지는 `shim.Wheel`, `shim.Click` 으로 만든다. 실제 터미널 확인은 tmux 에
SGR 시퀀스(`ESC [<65;x;yM` 등)를 `send-keys -l` 로 넣어 대화 스크롤, 목록 클릭/열기, `--no-mouse` 에서
1002/1006 모드를 켜지 않는 것을 봤다.
