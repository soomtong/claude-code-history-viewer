# 0014. 레이아웃 보강: 묶음 제목 선, 헤더 아래 선, 본문 왼쪽 여백

상태: 채택 (2026-10-24)

## 배경

0011 이후에도 화면이 허전하다는 피드백. 원인은 테두리가 없어서라기보다 다음 세 가지였다.

- 넓은 창에서 제목(왼쪽 끝)과 시각(오른쪽 끝) 사이가 비어 있다.
- 대화 헤더의 메타 줄과 본문 첫 줄이 같은 흐린 톤으로 붙어 경계가 없다.
- 목록의 날짜 묶음 제목이 흐린 글자뿐이라 구획으로 읽히지 않는다.

전체 테두리는 쓰지 않는다. 좌우 2칸과 위아래 2줄을 쓰고, 헤더/하단 띠와 틀이 겹치며, 마우스 복사에 `│` 가 섞이고,
박스 문자(East Asian Ambiguous)를 2칸으로 그리는 터미널에서는 오른쪽 테두리가 매 줄 어긋난다. 박스는 모달,
도움말, 제목 입력에만 쓴다.

## 결정

- 목록 묶음 제목(`chrome.lis` `group_header`): `  오늘 ─────` 처럼 제목 뒤를 흐린 선으로 줄 끝까지 채운다.
  오른쪽 1칸은 항목 시각 뒤 여백과 맞춘다. 폭이 모자라면 선 없이 제목만 남는다.
- 대화 헤더 아래(`header_rule`): 메타 줄 다음에 흐린 가로선 1줄. 본문 높이는 `height - 4`. `--compact` 면 헤더와 함께 생략.
- 대화 본문 왼쪽 여백 1칸: 표식 `›` `●` 이 화면 가장자리에 붙지 않고 헤더의 ` cci `, 가로선과 세로로 맞는다.
  본문 폭은 `width - 3`(왼쪽 여백, 스크롤바 앞 여백, 스크롤바).
- 새 문자나 폭 전제는 없다. 선은 기존 `divider` 와 같은 `─`, 같은 `st_faint`. NO_COLOR 에서도 모양이 남는다.
- 보류: 본문 최대 폭 제한. 넓은 창에서 시각이 멀어지는 문제는 남지만, 한 화면 정보량과의 트레이드오프라 설정값으로 따로 검토한다.

## 검증

- `src/tui/chrome.test.lis`: 묶음 제목 선과 헤더 선의 폭(24/60/100, 아주 좁은 폭), 대화 화면의 가로선 위치,
  본문 첫 줄 왼쪽 여백, 화면 줄 수가 높이와 같고 폭을 넘지 않음.
- tmux: 100x24, 50x10(1줄 항목, 스크롤바), `--compact`, `--no-color` 에서 색 코드 0개.
