# 0006. 메시지-줄 매핑과 렌더 캐시, 지연 렌더 (Phase 2.5)

상태: 채택 (2026-10-22)

## 결정 (src/tui/cache.lis)

- 캐시 키: `메시지 인덱스|message id|블록 수|폭|토글 서명|compact`. 블록 수를 넣어 증분 병합(같은 id 에
  블록이 추가됨)과 토글 변경 시 자연히 다시 렌더된다. 폭이 바뀌면 렌더러를 새로 만들며 캐시를 비운다.
- glamour 가 필요한 것은 텍스트가 있는 assistant 메시지뿐이다. 나머지는 바로 최종본으로 렌더한다.
- 지연 렌더: 먼저 모든 보이는 메시지를 캐시본 또는 평문 자리표시(`render_message(.., None)`, 캐시 `p|키`)로 배치하고,
  목표 줄 기준 `[y - h, y + 2h]` 범위에 걸친 자리표시만 glamour 로 바꾼 뒤 다시 배치한다.
  스크롤 키/마우스 처리 후 `ensure_rendered` 가 같은 범위에 자리표시가 있는지 보고 필요할 때만 relayout 한다.
- 화면 고정(anchor): relayout 전 맨 위 줄이 속한 메시지와 그 안의 오프셋을 기억했다가 같은 메시지로 복원한다.
  메시지가 숨겨졌으면 그 뒤 첫 메시지로. 자리표시 -> glamour 교체로 줄 수가 바뀌어도 보던 위치가 유지된다.
- 메시지-줄 매핑 `Span{msg, start, lines, prompt, full}` 은 relayout 마다 재계산(메시지 사이 빈 줄 1).
  `]`/`[`, `}`/`{`, 검색 매치 이동, 상태줄의 "i/n 메시지" 가 모두 이 매핑을 쓴다.
- 리사이즈는 0004 의 150ms 디바운스 후 relayout.

## 검증

- `src/tui/cache.test.lis`: 200턴(400 메시지) 합성 세션에서 첫 화면 glamour 렌더 30회 미만, `G` 후에도 60회 미만,
  `g` 로 돌아와도 캐시로 렌더 횟수 불변. 토글(thinking) 후 맨 위 메시지 유지.
